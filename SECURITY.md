# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security problem.

Report it privately through one of these channels:

- GitHub private vulnerability reporting: [Report a vulnerability](https://github.com/JitterCompany/sensor-link/security/advisories/new) on the Security tab.
- Email: security@jitter.company

Please include:

- The affected crate or tool, and the version or commit.
- What an attacker can do, and what they need first.
- Steps to reproduce, or a proof of concept.
- Whether you know of active exploitation.

We acknowledge and assess reports on a best-effort basis, and keep you informed while we work on a fix.
Please keep the details private until a fix is released, or until we agree on a date with you.

## How we handle vulnerabilities

- We track each report in a private GitHub security advisory.
- Fixes land on `master`. Older versions do not get security fixes.
- When the fix is released, we publish the advisory so users and downstream projects can act on it.

## Actively exploited vulnerabilities

Where we are involved in developing the affected code, we notify actively exploited vulnerabilities through ENISA's single reporting platform, as the EU Cyber Resilience Act requires (Art. 24(3) with Art. 14(1)).

## Incidents on our development systems

This covers the systems we provide to develop this code: the GitHub repository, its CI and its release artifacts.
If a severe incident affects their security, we notify it through ENISA's single reporting platform (CRA Art. 24(3) with Art. 14(3)).

## Informing users

After an actively exploited vulnerability or a severe incident, we inform users through a GitHub security advisory on this repository (CRA Art. 14(8)).

## Market surveillance authorities

Jitter cooperates with market surveillance authorities. Send requests to security@jitter.company.
On a reasoned request we provide this policy and the records behind it (CRA Art. 24(2)).
